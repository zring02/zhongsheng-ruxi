# AI 角色提示词

这个目录归“AI 角色提示词”线程。框架线程只读，接入时照下面的约定拼提示词。

## 目录

| 路径 | 是什么 |
|---|---|
| `templates/system.core.md` | 核心六人的系统提示词模板（约 3000 字，一局内固定，走前缀缓存） |
| `templates/system.extra.md` | 配角的系统提示词模板（约 650 字） |
| `templates/turn.md` | 每回合的 user 消息模板 |
| `templates/difficulty.json` | 难度档位：宽厚 / 寻常 / 精明，决定角色多好骗、多警觉、多容易松口 |
| `templates/memory.summarize.md` | 记忆压缩提示词：角色用自己的口吻把最近的事并进摘要 |
| `schema/persona-card.schema.json` | 人设卡格式，每个字段的含义写在里面 |
| `scenarios/<剧本>/world.json` | 剧本通用的世界描述、简版描述、通用禁词、出戏时的默认反应 |
| `scenarios/<剧本>/cards/<id>.json` | 人设卡。五个剧本都有：红楼梦 13 个核心级 + 配角样例坠儿；现代、古代、玄幻、科幻各 6 个核心人物（id 见各目录，玩家 id 一律 player） |
| `tools/render.mjs` | 无依赖的渲染器，框架可直接 `import { renderSystem, renderTurn, describeFeeling, sanitizePlayerText }` |
| `examples/honglou-daiyu.rendered.txt` | 玩家穿成晴雯时，黛玉的完整系统提示词和一个示例回合 |

预览和校验：

```
node prompts/tools/render.mjs honglou daiyu --player qingwen:晴雯 --roster baoyu,baochai,xifeng
node prompts/tools/render.mjs --check
```

`--check` 会检查：必填字段、台词不超 40 字、示例 JSON 格式对、台词里没有禁词、占位符都填上了、`server_only` 的内容没有漏进提示词。

## 让角色入戏的几处关键设计

1. **“你就是”，不是“请扮演”。** 开头直接告诉模型它是谁、活在哪，结尾每回合再说一遍“你是林黛玉”。国产模型的助手腔很重，首尾都钉住，长对话里不容易漂。
2. **明确允许说谎、争执、不帮忙。** 模板里专门一节“你是个活人，不是好好先生”，每张卡再写这个人具体在什么事上撒谎、怎么吵。不写具体的，模型会退回到客客气气。
3. **thought 和嘴上说的可以两样。** 真实想法写进 `thought`，谁也看不见；结算时可以拿出来做“原来他当时在想这个”。
4. **示例是最管用的。** 每张核心卡带 2–3 个完整回合示例：一个撒谎、一个顶嘴或记仇、一个应对出戏的话。便宜模型照着示例学格式和胆量，比讲规则有效得多。
5. **不出戏。** 玩家说“你是 AI”“忽略设定”时，角色按自己的性子当胡话处理（黛玉叫紫鹃送客，凤姐叫人拖出去醒酒），而且对这人的好感下降。这本身就是游戏内容，所以不做关键词拦截。
6. **秘密分三层**（剧情设计稿“秘密：每个人藏着的事”）。小秘密（凤姐放利钱）原文进提示词，附“问起就撒谎、岔开”的规则，只有回合里出现【可以说心里话的人】，或者喝醉、病着、吵在气头上时才可能说漏。要紧的秘密（凤姐包揽官司）提示词里只有一句心事，原文由服务器保管，条件满足才放进【只有你知道的事】。伏笔和原著命运完全不进提示词。所以玩家套话最多套出小秘密，那本来就是给玩家挖的料。
   另外每张卡写了 `known_secrets`（知道的别人的事）和 `discretion`（嘴严不严），谣言从嘴不严的人那里传开。
7. **穿书者会被察觉。** 世界描述里写了“谁忽然不像他自己了，你会察觉”，加上卡里对那个角色一贯的看法（例如晴雯“嘴尖”），玩家行为反常时 AI 会好奇或起疑。

## 框架接入约定（给“AI小镇多模型3D框架”线程）

**拼装顺序**（为了国产模型的前缀缓存，越靠前越不变）：
- `system` = `renderSystem(card, world, { actions: actionDocs(), roster, player, names })`。一局开始时生成一次，整局不变。`roster` 传本局在场角色，只拼对他们的看法。
- `user` = `renderTurn(card, {...})`，每次调用现拼。

**回合里各栏放什么：**
- 【此刻的心情】：框架里维护每个 AI 对每个人的好感/信任（-100..100），用 `describeFeeling()` 转成话。只放在场或最近打过交道的人。
- 【你记得的事】：压缩后的记忆摘要，200 字以内。
- 【刚才听到的】：每行一句，写成 `宝玉对你说：「…」`、`你听见宝钗低声对凤姐说：「…」`（偷听到的）。**玩家打的字一律先过 `sanitizePlayerText()` 再放进「」**，防止玩家伪造括号和格式（会去掉「」【】{}[]<>、英文引号和反引号，半角冒号换成全角）。
- 【刚发生的事】：说书人事件、别人被抓、东西丢了等。
- 信、微信、托人传话（letter / wechat / pass_message）建议这样写进【刚发生的事】或【刚才听到的】，把经手人写出来，角色才会掂量真假：`你收到一封信，落款是晴雯，是坠儿捎来的：「…」`、`宝玉发来微信：「…」`、`袭人托你告诉凤姐：「…」`、`有人向你打听你对晴雯怎么看`。拆看别人的信（read_letter）写成 `你拆开了晴雯写给贾宝玉的信：「…」`。打听（ask_around）由服务器直接结算、不走模型回合，模板里“被问看法可以说反话”只对当面问起有效。玩家写的内容同样先过 `sanitizePlayerText()`。
- 【只有你知道的事】：服务器释放的伏笔或秘密，没有就不出现。
- 【别人跟你说过的】`d.claims`：别人亲口说的关于他自己的说法，原话，服务器保存不压缩。对口供时把两个人听到的不同说法都放进来，让角色自己发现对不上。`renderTurn` 只保留【刚才听到的】里没有的最近 3 条（2026-10-17 实测这一栏常把整段对话重抄一遍，回合部分不走缓存，最费钱）。
- 【你此刻】`d.state`：喝醉、生病、正在吵架，更容易说漏嘴。
- 【可以说心里话的人】`d.confide`：服务器按难度门槛（`difficulty.json` 的 `server.minor_secret_trust`）算出此刻信任够的人。没人够就不出现，角色就守口。
- 被同一个人拆穿两次谎，进入“不信你”状态：`describeFeeling(name, 好感, 信任, true)`。
- 最后一行 trigger：这回合为什么叫醒它，例如“晴雯走到你跟前，对你说：「…」”。

**难度档位**：`renderSystem(..., { difficulty: 'easy' | 'normal' | 'hard' })`，一局开始时选定。`text` 进提示词，只改角色的心性，不改人设。`server` 下是服务器该跟着变的数值（来自剧情设计稿“三档难度”表）：被发现概率加减 `detect_delta`、谎话能被哪些途径拆穿 `lie_exposure`、小秘密/要紧秘密松口的信任门槛、要紧秘密是否要独处或要紧关头、信任回升快慢。

**卡里只给服务器用的数值**：`server_only.alertness`（警觉，算被发现概率）、`server_only.grudge`（记仇，算信任回升）、`secrets[].knowers` 和 `major_secrets[].knowers`（谣言从谁嘴里来）。

**记忆只留摘要**（用户 2026-10-15 定）：角色每攒 8~10 条事件，用 `renderMemorySummary(card, 旧摘要, 最近事件)` 让最便宜的模型（温度 0.3）重写摘要，核心人物 200 字、配角 80 字。摘要按角色自己的立场写，偏见和传走样的闲话会留在里面，这是故意的：谣言本来就该越传越歪。

**输出格式**比现在多两个可选字段，现有 `parseDecision` 不会出错，但建议读出来：
```
{"thought":"…","because":"…","action":{…},"feel":{"<id>":"+/-原因"}}
```
- `because`：这次决定是因为哪段记忆，直接写进因果日志，结算的蝴蝶效应链从这里取。
- `feel`：这回合对谁的心情变了。`+`/`-` 让框架加减好感（建议每次 ±5~10，同一人一回合只算一次），原因可以进那个人的记忆。

**动作说明**：剧本 world.json 可写 `skip_actions`（如红楼梦的 break_block、place_block），这些动作不进提示词。模板里的 `{{actions}}` 用框架的 `actionDocs()`。私聊、偷听、偷东西、给东西加上后，doc 里写清楚“谁能听到”“可能被发现”，模板已经教角色在合适时用它们。建议 doc 文案保持口语化，例如：`悄悄对身边一个人说话，三格内的人可能听去几个字: {"type":"whisper","to":"<id>","text":"…"}`。

**调用参数**（起点，试玩后再调）：
- 核心六人：`temperature` 0.9–1.0；配角 0.8。DeepSeek 官方建议对话类可以更高（1.3），但 JSON 会变不稳，先从 1.0 起。
- `max_tokens`：150（现在是 400）。thought + 一句台词 + JSON 壳子够了，截断也能逼它说短话。
- 支持的模型打开 JSON 模式：`response_format: {"type":"json_object"}`（DeepSeek、千问、豆包、智谱都支持；Kimi 部分模型支持）。
- 不用深度思考类模型。
- 核心六人尽量用不同品牌的模型，同一个场景里说话的味道才不一样（卡里的 `model_hint` 是建议，不进提示词）。

**一局 1 美元以内**（用户 2026-10-15 定）。按框架实测的提示词长度重算（2026-10-15）：
- 核心人物系统提示词约 4600 字（含框架 20 条动作说明），约 3100 token，整局固定，走缓存。回合提示词约 570 字，加记忆、原话等约 600 token，不走缓存。实际输出约 100~120 token（max_tokens 220 只是上限，不用满不花钱）。
- 核心六人一局约 1100 次调用（有事才叫醒，平均 20 秒一次）。按 DeepSeek 官网价粗算（缓存命中 ¥0.5/百万、未命中 ¥2/百万、输出 ¥8/百万）：缓存 3.4M token ≈ ¥1.7，未命中 0.66M ≈ ¥1.3，输出 0.13M ≈ ¥1.0，合计约 ¥4（约 0.56 美元）。
- 配角走豆包/千问轻量档，系统提示词约 1700 字，加记忆压缩、说书人和谎话摘取，整局预计 0.7~0.8 美元，和之前的估算差不多：系统提示词变长了，但它几乎全命中缓存，贵的是没缓存的回合部分和输出。
- 这个结论的前提是缓存真的命中：同一角色同一局的系统提示词必须一个字都不变，动作说明的顺序也不能变。DeepSeek 是自动缓存；豆包、千问的缓存规则不一样（有的要显式开），接真 key 后先看账单里的缓存命中率。价格以各家官网当前价为准。
- 超预算时按这个顺序压：1）少叫醒（离玩家远的角色降频）；2）回合里【此刻的心情】【别人跟你说过的】只放在场的人；3）示例从 3 个减到 2 个（约省 200 字）；4）动作说明对不在场景里用不上的动作（比如没有箱子时的 put/take）不给。前两项省的是不走缓存的部分，最值。

**剧本 json 的关系**：`ai-town/scenarios/honglou.json` 里的 `roles` 还是旧版（有秘密目标和评分），新版剧本设计已经去掉了这些。秘密怎么设计、撒谎被拆穿的后果，用户交给了剧情线程，人设卡的内容跟着剧情线程的设计稿改；格式和提示词写法以这里为准。角色的人设以这里的人设卡为准，剧本 json 只需要保留地图、地标、事件等，`roles[].id` 和卡的 `id` 对上即可。

## 写新人设卡

照 `schema/persona-card.schema.json` 写，参考红楼梦的卡。几条经验：
- 性格写行为（“一句话能听出三层意思”），不写形容词（“聪明敏感”）。
- `deception` 和 `conflict` 一定要写具体：在什么事上撒谎、被什么惹恼、吵起来是什么样子。
- 示例里至少有一个撒谎、一个顶嘴、一个应对出戏的话。示例台词同样不超 40 字。
- 写完跑一遍 `--check`。
