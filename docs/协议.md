# 前后端协议（v2：剧本 / 沙盒 / 玩家）

服务端：`src/server.ts`。所有类型定义见 `src/types.ts`，动作说明见 `src/actions.ts` 里每个处理器的 `doc`。

## HTTP

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/scenarios` | 剧本列表 `ScenarioSummary[]`（见下） |
| GET | `/api/game` | 当前一局的摘要 `GameSummary`；没有开局时 `{status:'none'}` |
| POST | `/api/game/new` | 开新局，body = `GameOptions`（见下），返回 `GameSummary`；参数不对返回 400 `{error}` |
| POST | `/api/game/end` | 提前结束：说书人写结局（几秒到十几秒），返回带 `ending` 的摘要；同时会广播 `ending` 事件 |
| POST | `/api/game/save` | 手动存档 `{ok,id}`（沙盒和剧情模式都每 60 秒自动存一次） |
| GET | `/api/saves` | 存档列表 `[{file,id,savedAt,scenarioName,mode,status,playerName,days}]` |
| POST | `/api/game/load` | 读档 `{file}` → `GameSummary` |
| GET | `/api/endings` | 结局图鉴 `[{gameId,at,scenarioId,scenarioName,mode,playerName,days,title,text,epilogues:[{id,name,text}],chain,reveals,chapters:[{day,title,text}],stats}]` |
| GET | `/api/game/export` | 下载本局实际生效的剧本 JSON（沙盒自定义已合并，可以分享给别人当剧本）。**全貌接口**：有玩家且这局还在进行时返回 403（里面有伏笔、命运、别人的心愿），结束后或观察局才给；`/api/game/causal`、`/api/game/replay`、`/api/game/recap`、`/api/state` 同样 |
| GET | `/api/game/causal` | 因果日志 `[{t,day,agentId,name,thought,because?}]`（结算串“蝴蝶效应链”用） |
| GET | `/api/game/calls` | 每次模型调用的记录（开了 `CALL_LOG=1` / `CALL_LOG_DIR` 才有）：`{enabled, file:<文件名，不含路径>, calls:[{n,t,e,who,name,tier,purpose:'decide'\|'storyteller'\|'memory',provider,model,maxTokens,temperature,json,systemHash,systemChars,system?(首次),prompt,output,error?,ms,usage:{promptTokens,cachedTokens,completionTokens},parse?:{ok,fatal?,error?,action?,thought?,because?,feel?,goal?}}]}`。全貌接口，有玩家且进行中时 403；没开局 `{status:'none'}` |
| GET | `/api/game/recap` | **结算素材**（结算动画、分享海报都从这里取）：`{id,status,scenario:{id,name,genre},mode,days,player:{id,name,public,wish,color}|null, ending:{title,text,epilogues,chain,reveals}|null, chapters, stats:{steals,caught,gives,whispers,says}|null, world:{size,before:<开局世界 base64>,after:<现在世界 base64>,changedBlocks,playerBlocks:[{t,day,agentId,op,block,pos}]}, people:[{id,name,tier,color,public,wish,trust:<对玩家的信任>,notes:[<记得玩家做过的事>],epilogue}], touchedEvents, causal:[{day,name,thought,because}], highlights:[<关键事件行>], shareText:<可直接发出去的几行文案>}`。结束前也能调，拿到的是进行中的数据 |
| GET | `/api/difficulties` | 难度档位 `[{id,name,text}]` |
| GET | `/api/game/cost` | 本局模型花费（没开局时 `{status:'none'}`） `{usd,cny,budgetUsd,level:'ok'\|'saving'\|'over',calls,promptTokens,cachedTokens,completionTokens,byProvider:{<provider>:{calls,cny}}}`。花到预算八成进 `saving`（路人没事不想、核心人物发呆间隔加倍），花完进 `over`（所有真模型换成内置假模型继续过日子，说书人改用内置事件）。预算在 models.json 的 `budget.usdPerMatch`（默认 1 美元，环境变量 `BUDGET_USD` 可改） |
| GET | `/api/game/replay` | **回放素材**：`{id,status,scenario:{id,name,genre},mode,playerId,world:{size,start:<开局世界 base64>},landmarks,agents:[{id,name,color,kind,tier}],frameIntervalMs:2000,facings:['north','east','south','west'],emotes:[…],frames:[{t:<开局后毫秒>,a:[[x,y,z,朝向下标,表情下标+1(0=无)]…按 agents 顺序]}],events:[WorldEvent & {e:<开局后毫秒>}…全部，观察者视角],chapters,ending}`。前端按时间轴重演：帧的 `t` 和事件的 `e` 是同一条时间轴（开局后毫秒，暂停不计；事件自带的 `t` 是墙上时间，别拿它对帧），位置帧之间插值，方块改动从 `block` 事件里取，对话从 say/whisper 事件里取。有玩家且进行中时 403（见 export）；没开局 `{status:'none'}` |
| GET | `/api/models` | 模型名单与分档 |
| GET | `/api/state` | 调试用：快照 + 最近事件 |

### ScenarioSummary
```json
{ "id":"honglou", "name":"穿书：红楼梦", "genre":"book", "tagline":"…", "background":"…", "playerIntro":"…",
  "duration":{"minutes":60,"days":3},
  "landmarks":[{"id":"spawn","name":"怡红院","description":"…"}, …],
  "roles":[{"id":"daiyu","name":"林黛玉","tier":"core","public":"寄居贾府的表小姐","playable":true,"color":"#…"}, …],
  "coreSets":null|{"player":["baoyu",…],"baoyu":[…]},
  "player":{"id":"qingwen","name":"晴雯","public":"…","personality":"…","wish":"…","knot":"…"},
  "currency":{"name":"铜钱","start":30,"askCost":5}, "features":{"wechat":false},
  "storytellerActivity":"normal" }
```
`genre`: modern | ancient | fantasy | scifi | book | custom。AI 角色的心愿/心结/命运不会给前端。
`currency`：本剧本的游戏币（现代=元、古代/红楼=铜钱、玄幻=灵石、科幻=配给点），玩家开局揣 `start` 个、AI 揣一半，它就是背包里的一件东西，可以 give、被偷；`askCost` 是托人打听一次的价钱。`features.wechat` 为 true 的剧本（现代）多一个 `wechat` 动作。

### GameOptions（POST /api/game/new 的 body）
```json
{ "scenarioId":"honglou", "mode":"story",
  "playerRole":"player",
  "playerName":"阿明", "playerWish":"让黛玉活下来", "seed":42, "difficulty":"normal",
  "sandbox":{ "customText":"把红楼梦搬到太空站", "extraRoles":[RoleDef…], "removeRoles":["xifeng"],
              "storytellerActivity":"dramatic", "minutesPerSecond":1, "disasters":false, "runWhileAway":false } }
```
- `mode`: `story`（限时：60 分钟 = 3 个游戏日 × 四段〔早上 / 中午 / 傍晚 / 夜里〕× 5 分钟，有收网大事）| `sandbox`（不限时，`sandbox` 字段才生效）。
- `playerRole`: `null` = 观察模式（没有玩家）；`"player"` = 剧本给的主角模板；或某个 `playable:true` 的角色 id（那个角色就不再由 AI 演）。
- 开新局后前端先展示 `GameSummary.opening`（开场卡：处境、身边六个人和自己对他们的看法、自己知道的小秘密、心愿；30 秒能读完），关掉卡就开演。第一个人会在 30 秒内上门。
- `difficulty`: `easy`（宽厚）| `normal`（寻常，默认）| `hard`（精明）。决定角色多好骗、多警觉、多容易松口：被发现概率 ±10%、秘密松口的信任门槛、信任回升快慢；档位列表见 `GET /api/difficulties`（`[{id,name,text}]`，没开局时的 `init` 消息里也带 `difficulties`）。
- `RoleDef`（自定义角色）：`{id,name,tier?,public,personality,speech?,wish?,knot?,relations?,home?,color?,inventory?,model?:{provider,model},playable?,alert?}`，id 只能是字母、数字、下划线、连字符。`playerName`、`playerWish` 会先过清洗（去括号引号、半角冒号换全角）。

## WebSocket `/ws`

连接地址加 `?observer=1` 就是观察者视角（什么都看得到）；否则默认是本局玩家的视角：看不到别人的内心想法、打算、信任值，也看不到别人之间的私聊（除非自己偷听到了）、别人偷东西得手。**有玩家且这局还在进行中时观察者视角锁住**（和全貌接口一样）：这时 `?observer=1` 或 `hello{observer:true}` 会被按玩家视角处理，并收到一条 `reject` 说明；观察局（没有玩家）或结束后随意。

服务端 → 客户端：
- `init`：连上时和每次开新局/读档时发。`{type:'init', world:{size:{x,y,z}, data:<base64 的 Uint8Array>}, blockTypes:[{id,name,cn,color,solid,breakable}], landmarks:[{id,name,pos,radius,description}], events:[WorldEvent…最近 80 条], game:GameSummary, viewer:<玩家id|null>, time, day, phase, paused, agents:[AgentSnapshot…]}`。没开局时只有 `{type:'init', game:{status:'none'}, scenarios:[ScenarioSummary…]}`。
- `state`（每 200ms）：`{type:'state', game:{status,day,phase,time,minutesLeft,totalDays}, cost:{usd,level}, time, day, phase, paused, agents:[AgentSnapshot…]}`（`cost.level` 变成 saving/over 时会同时广播一条 `system` 事件说明）
- `event`：`{type:'event', event:WorldEvent}`
- `blocks`：`{type:'blocks', changes:[{x,y,z,id}]}`
- `reject`：`{type:'reject', text}`——玩家动作参数不对，或对说书人请求的回执

客户端 → 服务端：
- `{type:'hello', observer:true|false}` 切换视角（会重发 init）
- `{type:'control', action:'pause'|'resume'}`
- `{type:'player_action', action:Action}` 玩家动作，Action 格式同 AI（见下）；会打断玩家正在走的路
- `{type:'storyteller_request', text:'让镇上来一条龙'}` 中途加剧情，说书人会把它安排成一个事件。有玩家的局只有玩家本人的连接能发；文字先清洗、最多 120 字，一分钟最多一条、最多排两条（超了 `reject` 说“过一分钟再说”）

### AgentSnapshot
`{id,name,kind:'ai'|'player',tier:'core'|'extra',public,provider,providerLabel,model,color,alive,pos:{x,y,z},facing,moving,thinking,emote,jailed:<还要关几秒，0=没关>,eavesdropping:<正在偷听谁|null>,location:<地标名|null>,lastThought,goal,wish,inventory:{物品:数量},trust:{<id>:-100..100},affection:{<id>:-100..100},stats:{steals,caught,gives,whispers,says}}`
玩家视角下别人的 `lastThought/goal/wish/trust/affection/eavesdropping` 是空的，`inventory` 是空的，`stats` 只有 `caught` 和 `says` 是真的。`inventory` 的 key 可能是方块英文名（用 blockTypes 翻成中文）或剧本物品的中文名（直接显示）。

### Action（玩家能发的动作，和 AI 一样）
```
{"type":"turn","direction":"north|east|south|west|left|right"}
{"type":"move","steps":1-6}
{"type":"walk_to","target":"<地标id>"} / {"type":"walk_to","x":10,"z":12}
{"type":"approach","target":"<人的id|地标id>"} / {"type":"approach","target":{"x":10,"y":8,"z":12}}   走到跟前并面向
{"type":"break_block","target":"front|front_up|front_down"}
{"type":"place_block","block":"plank","target":"front"}
{"type":"say","text":"…","to":"<可选 id>"}                      10 格内都听得到
{"type":"whisper","to":"<id>","text":"…"}                        要在对方 2 格内
{"type":"eavesdrop","target":"<id>"}                              6 格内，持续 60 秒，可能被发现
{"type":"steal","target":"<id>","item":"<可选>"}                 2 格内，可能被抓→关 90 秒
{"type":"give","to":"<id>","item":"<物品>","count":1}            2 格内
{"type":"put","item":"<物品>","count":1} / {"type":"take","item":"<物品>","count":1}   面前要有箱子（方块 chest）
{"type":"emote","emote":"wave|laugh|think|sad|dance|sleep|angry|love"}
{"type":"idle","seconds":5}
{"type":"ask_around","target":"<id>","about":"<可选 id>"}     花 currency.askCost 个游戏币托人打听 target 对你（或对 about）的看法：好感、信不信、记得你什么，结果以 notice 发给自己；两成几率走漏，target 收到“有人在打听你”的 notice
{"type":"pass_message","via":"<id>","to":"<id>","text":"…"}  传话：让跟前（2 格内）的 via 把话带给 to。本质是对 via 的一句 whisper（事件带 relayTo），via 听到的是“某某托你告诉某某：「原话」”，带不带、改不改字看 via
{"type":"write_letter","to":"<id>","text":"…"}               写信：信成为背包里的一件东西「X写给Y的信」，可以 give、托人 give、put 进箱子，也可能被 steal。谁拿到手谁就读了（收到 letter 事件）
{"type":"wechat","to":"<id>","text":"…"}                     发微信：只在 features.wechat 的剧本（现代）可用，不用在跟前，只有对方收到（他可以转述）
{"type":"read_letter","item":"<信的东西名>"}                 拆信：拆开手里一封不是写给自己的信。写给自己的信到手就自动读了；带信的、偷信的、从箱子取的人拿到的是没拆的信（notice 提示），拆开才有 letter 事件
```
- 信的东西名：`X写给Y的信`，同一人再写给同一人叫 `X写给Y的第2封信`，以此类推。作者拿回自己的信只是拿回。
- 托人打听：先扣钱并提示“等回话”，5–15 秒后另一条 notice「托的人回话了：…」；同一个人没回话前不能再托；回话只含对方亲身记得的事（道听途说的不算）。
- 送东西加信任递减：第一次 +15，之后 15/(n+1)；送游戏币要送到 `askCost` 那么多才算一份整礼（送 1 个铜钱几乎不加）。
- `emote` 只接受列出的八个动作名。
被关着的时候只能 turn / say / whisper / emote / idle，以及 ask_around / pass_message / write_letter / read_letter / wechat。

### WorldEvent（`kind` 和字段）
| kind | 字段 | 说明 |
| --- | --- | --- |
| say | agentId, text, to? | 公开说话 |
| whisper | agentId, to, text, overheardBy?, relayTo? | 私聊（只有当事人和偷听到的人收到）。带 `relayTo` 的是传话（pass_message）：text 是托带的原话，to 是带话的人；他之后对 relayTo 说什么是另一条 say/whisper 事件，两条对照就知道有没有改字或压下 |
| emote | agentId, emote | |
| move / arrive | agentId, target | 动身 / 到达 |
| block | agentId, op:'break'\|'place', block, pos | |
| give | agentId, to, item, count | |
| chest | agentId, op:'put'\|'take', item, count, pos | |
| sneak | agentId, what:'steal'\|'eavesdrop', target, item?, text | 得手，只有当事人看到 |
| caught | agentId, what, target, by, penalty | 被当场抓住，公开 |
| fail | agentId, text | 没做成，只有当事人看到 |
| notice | agentId, text | 只有当事人看到的私下消息（发觉东西丢了、说书人悄悄说的往事、被关/放出、打听的结果、写好了信、“你想起有话要跟某人说”〔玩家 5 分钟没人搭理时说书人派核心人物来访〕） |
| wechat | agentId, to, text | 微信，只有双方收到 |
| letter | agentId(读信的人), from, to, text, item, via? | 有人读了一封信：收信人收到，或别人拆开了。`via` 是经手人（替作者转交的人，或 `chest` = 从箱子里取的）。只有读信的人（和观察者）看到 |
| thought | agentId, text, because? | 内心想法（观察者视角才有） |
| error | agentId, text | 模型出错（观察者视角才有） |
| story | title, text, participants?, requestedBy? | 说书人投放的事件，公开 |
| chapter | day, title, text | 一天结束的章回；玩家回来时“你不在的时候”也用这个 |
| ending | title, text, epilogues:[{id,name,text}], chain:[{text}], reveals:[{title,text,participants}] | 一局结束。`chain` = 蝴蝶效应链（玩家的小举动引出的连锁反应，3–5 幕，按时间演）；`reveals` = 感人的揭晓“原来是这样”（最多两段，可能为空）。结算动画按 结局名 → chain 逐幕 → reveals → 每个核心人物的 epilogue → 结局卡 的顺序演 |
| game | text, day, phase, audience? | 开局、天亮、中午、傍晚、入夜、结束中；`audience:'player'` 的是写给玩家看的开场白/收尾，AI 不会“听到” |
| system | text | 暂停/继续、预算档位变化等 |
所有事件都带 `t`（毫秒时间戳）。
