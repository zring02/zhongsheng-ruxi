# API 用谁的？怎么不亏还能挣钱（2026-10-17）

> 注意：还没用真模型跑完过一整局，下面的成本都是估算。等真模型测试出了实际账单，再按实际数字校正。

## 结论
1. **默认用我们的 API（官方托管），同时允许玩家填自己的 key（BYOK）**。大多数玩家不会去申请 API key，只做 BYOK 等于把普通玩家挡在门外。只做托管的话，买断制一定会亏。
2. **买断价格里只包含有限的托管额度，用完后按局买点数，或者切换成自己的 key**。不要做"买断后无限托管"。
3. **先把每局成本从约 ¥5 压到 ¥1–1.5**，这样定价才有空间。

## 算账依据
现在的估算（提示词线程的数字，和我按 deepseek-flash 价格复算的结果一致）：每局约 $0.7，合 **¥5 左右**。
- 假设：12 个角色，60 分钟，平均约 2000 次调用；每次输入约 3000 token，其中 80% 命中缓存；每次输出约 100 token。
- 未命中缓存的输入：1.3M × ¥2.16 = ¥2.8
- 命中缓存的输入：5.2M × ¥0.0432 = ¥0.2
- 输出：0.2M × ¥8.64 = ¥1.9
- 这里贵的是**未命中缓存的输入和输出**，命中缓存的部分几乎不花钱。

买断能扛多少局：
- 售价 ¥48，Steam 抽成 30%，再扣税、退款，到手约 ¥30。
- 按 ¥5 一局算，**玩 6 局就开始亏**。如果成本压到 ¥1.5，可以撑约 20 局。
- 少数重度玩家会玩几十局，所以买断不能包含无限托管。

众筹档位可以直接套这个结构：早鸟买断 ¥38 加 20 局额度；高档位 ¥98 加 60 局，再给角色署名、专属结局等。

## 把成本压到 ¥1–1.5 的方法（按收益从大到小排）
1. **只让玩家附近的角色调用模型**。不在镜头里的角色由说书人每个时段写一条摘要，不用每 20 秒都调一次。预计调用次数能减半以上。
2. **龙套角色不调大模型**。用规则加台词模板，或者多个龙套合并成一次调用来批量生成。
3. **固定前缀保持字节完全一致**，把缓存命中率做到 90% 以上：人设卡、世界设定放在最前面，变化的内容放在最后。
4. **压缩输出**：限制最大输出 token 数，回复控制在 40 字以内（已经在做），JSON 字段名尽量短。
5. **没事发生时降低调用频率**（框架已经有 80% 省钱模式，可以默认更激进一些）。
6. **走模型价格最低的路线**：几家国产模型轮流用，按实时价格选；如果有错峰折扣也可以用（DeepSeek 目前非高峰时段半价，高峰是工作日北京时间 9–12 点和 14–18 点，价格以官网为准）。
7. 本地小模型（Ollama，接口已经支持）只适合有显卡的玩家，作为 BYOK 之外的另一个选项，不要当主路线。

## 防止亏本的保险
- 每个账号每天设托管局数上限，防止被刷，也防止有人拿托管接口当免费 API 用。
- **key 只放在我们的服务器上，客户端拿不到**。模型调用全部经过我们的服务器转发。
- 每局 $1 的硬上限保留不动。

## 合规（只是提示，需要找专业人士核实）
- 在国内由我们托管模型、面向公众提供对话：可能需要做**生成式 AI 服务备案或登记**，还要接内容安全过滤。如果只是调用已经备案的大模型 API，可能只需要走登记流程，具体要咨询。
- 在国内正式上架收费：需要**游戏版号**。只在 Steam 国际区发售可以先绕开版号，但面向国内玩家的风险需要核实。
- BYOK 能降低一部分风险，但不能免除内容审核责任。
